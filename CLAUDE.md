# Quantum UI v2

## Project Structure

- `apps/quantum-ui/` — the Quantum UI app (all work happens here)
- `apps/v4/` — pristine upstream shadcn/ui reference (never modify)
- `packages/shadcn/` — shadcn workspace package (must be built once via `just setup`)

## Just Commands

- `just setup` — install deps + build shadcn package (run once after clone)
- `just run-dev` — fast dev server (skips registry build)
- `just run` — production build + serve (all routes pre-compiled, instant navigation)
- `just build-registry` — rebuild the component registry (needed after modifying registry source files)
- `just warm` — pre-compile all dev routes after `just run-dev` starts (run in a separate terminal)

## Dev Server Notes

- First page load in dev mode is slow (Turbopack lazy compilation) — this is normal
- `just warm` hits all major routes to force compilation upfront
- `just run` avoids this entirely by pre-building everything
- Clear `.next` cache (`rm -rf apps/quantum-ui/.next`) if you see stale errors

## Adding New Components

### Workflow

1. Study the component in shadcn/ui or a fork (check `apps/v4/` for the upstream version)
2. Modify the component in `apps/quantum-ui/registry/new-york-v4/ui/` — apply Quantum styling (e.g. `rounded-full` for buttons)
3. Create a demo page at `apps/quantum-ui/app/(app)/demos/{component}/page.tsx`
4. Create component docs at `apps/quantum-ui/content/docs/components/radix/{component}.mdx`
5. Add the component to the docs sidebar in `apps/quantum-ui/components/docs-sidebar.tsx` (`COMPONENT_ITEMS` array)
6. Update the components index at `apps/quantum-ui/content/docs/components/index.mdx`
7. Run `just build-registry` if you changed files in `registry/`

### Creating Demo Pages

Demo pages live at `apps/quantum-ui/app/(app)/demos/{component}/page.tsx`. These are standalone pages that show all variants, sizes, and states. Import components directly from the registry:

```tsx
import { Button } from "@/registry/new-york-v4/ui/button"
```

### Creating Docs Pages with Inline Previews

Component docs use MDX at `apps/quantum-ui/content/docs/components/radix/{component}.mdx`.

For inline previews with collapsible code, use the `InlinePreview` component pattern:

1. Create preview components in `apps/quantum-ui/components/docs/{component}-demos.tsx`
2. Each preview wraps `InlinePreview` from `@/components/docs/inline-preview`
3. `InlinePreview` takes `children` (the live demo) and `code` (string to display)
4. Code gets Shiki syntax highlighting and shows with a gradient overlay + "View Code" button
5. Register the preview components in `apps/quantum-ui/mdx-components.tsx` (both import and export)
6. Use them in the MDX file as `<ButtonVariantsPreview />` etc.

**Important:** The `code` prop must manually match the rendered JSX — there is no auto-sync. Keep them in sync when making changes.

**Why not use `ComponentPreview`?** The native `ComponentPreview` resolves components from the registry index (`registry/__index__.tsx`), which is auto-generated by `just build-registry`. Custom examples added to the `registry/new-york-v4/examples/` directory are NOT automatically picked up by the build — only examples defined in the upstream shadcn package registry schema get indexed. Use `InlinePreview` for custom demos instead.

### Docs Page Structure

Follow this pattern for each component docs page:

```
Hero preview (condensed, showing the component in action)

## Usage
Import statement + basic usage code

## Examples
### Variants
Description of what the prop does
<Preview with all variants in one row>
Property/Description table

### Sizes
(same pattern — one style, vary only the independent variable)

### Other features...
(with icon, loading, as child, etc.)

## Demo
Link to /demos/{component}

## API Reference
Prop/Type/Default table
```

**Key principle:** Each example section should use one consistent style and only vary the independent variable being demonstrated. For example, sizes demo uses `variant="outline"` on all buttons, only changing the `size`.

### Docs Sidebar

Component items are hardcoded in `apps/quantum-ui/components/docs-sidebar.tsx` in the `COMPONENT_ITEMS` array:

```tsx
const COMPONENT_ITEMS = [
  { name: "Button", href: "/docs/components/button" },
] as const
```

Add new entries as components are ported.

### Registry System

- `registry/__index__.tsx` is auto-generated — don't rely on manual edits surviving a `just build-registry`
- Component source files live in `registry/new-york-v4/ui/`
- Example files live in `registry/new-york-v4/examples/`
- The native `ComponentPreview` MDX component works for examples that exist in the upstream registry (e.g. `button-demo`, `button-with-icon`)
- For custom examples, use `InlinePreview` instead
