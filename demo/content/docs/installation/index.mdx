---
title: Using Quantum UI
description: How to use Quantum UI components in your projects, with or without an LLM.
---

Quantum UI components are just code. There is no CLI or package to install — you read the source, copy what you need, and adapt it to your project.

## For LLM-Assisted Development

The most effective way to use Quantum UI is with an LLM (Claude, GPT, etc.). Here's the workflow:

### 1. Discover Components

Browse the [component catalog](/docs/components) to find what you need. Each component page shows a live preview and its source code.

### 2. Fetch Component Source

Every component is available as a JSON registry entry. An LLM can fetch a component's source programmatically:

```
GET /r/styles/new-york-v4/[component-name].json
```

The response includes the component's source files, dependencies, and any related utilities.

### 3. Adapt to Your Project

Prompt the LLM to take the component source and adapt it to your project's conventions:

```
Take the Button component from Quantum UI and adapt it for my project:
- Use our existing design tokens (colors from tailwind.config)
- Match our naming conventions (PascalCase files, barrel exports)
- Replace any Quantum-specific imports with equivalents from our codebase
```

### 4. Example Prompts

**Porting a component:**
```
Read the Quantum UI Button component source. Rebuild it in my project
using my existing primitives and tokens. Don't copy it verbatim —
adapt the interaction pattern and layout to match my design system.
```

**Creating a variant:**
```
Based on Quantum UI's Button component, create a "ghost" variant
that uses my project's color tokens and spacing scale.
```

**Building something new:**
```
Look at how Quantum UI structures its form components (Field, Input,
Select). Build a new DatePicker component that follows the same
composition patterns and uses the same design tokens.
```

## Manual Usage (Without an LLM)

1. Find the component you need in the [component catalog](/docs/components).
2. Read its source code in `apps/quantum-ui/registry/`.
3. Copy the relevant files into your project.
4. Update imports to match your project structure.
5. Adjust design tokens (colors, spacing, radius) to fit your system.

## Project Structure

Components live in the registry under `registry/`:

- `bases/` — Base UI primitive components (Radix, Base UI)
- `styles/` — Styled component variants and CSS
- `icons/` — Icon library integrations
